# 国外正文语言与表达复核

先运行 `python -X utf8 "${SCRIPTS_DIR}/writing_profile.py" --project-root "${PROJECT_ROOT}" --bundles`，验证 `.story-system/WRITING_PROFILE.json` 并加载全部主辅题材包与正文语言包。缺损、版本不符或 国外题材 draft 未授权时停止，不用国内默认补齐。流程边界见 `../../../references/writing-rules/README.md`。

1. 先按现有事实报告处理可验证矛盾，不擅自改剧情、节点、人物知识和关系状态。
2. 按 `body_language` 通读全文，检查具体指代、POV、时态、术语、对白/内心标点及场景信息次序；正文为英文时直接改英文表达，说明用中文。
3. 依据全部已选题材的读者承诺观察成长、机制、关系等体验，明确指出哪段缺少什么信息或行动。
4. 给可选择的改写与理由，尊重作者已有文风；不用词频、固定句长、停顿配额、said 标签比例或固定“至少改三处”规则推断质量。
5. 单独记录语言建议；不增加事实 reviewer 维度、issues 或 blocking，不写入事实 metrics，不伪造外部母语编辑、AI 检测或平台认证。

建议报告：

```text
[语言与表达建议]
- 配置：overseas / en（或 zh）；主类型 + 全部辅类型；章长与单位；POV/时态
- 位置与原文：...
- 观察：具体歧义、语法、声音或题材兑现问题；事实不确定时另请事实链查证
- 可选修改：...
- 理由与代价：...
- 未验证：目标平台格式、母语编辑、读者反馈等实际缺项
```

没有发现表达问题时如实记录观察范围，不为了满足固定改写次数制造修改。若只查了片段，不宣称全文已审；若是短示例，不宣称达到全章或长篇质量。
